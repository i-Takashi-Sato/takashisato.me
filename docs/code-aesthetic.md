# Code Aesthetic — The Proper Ending Index

The repository is part of the published work. Code quality is therefore judged by the same standard as typography and spatial design: unnecessary cleverness, accidental duplication, and unexplained state are defects.

## Principles

1. **One source of truth for research facts.** Titles, identifiers, version dates, hashes, and author identity belong in the canonical research model and are rendered outward from there.
2. **Readable source, compact output.** Human-authored Python, CSS, and JavaScript stay readable. Generated assets may be compact only when the transformation is deterministic and tested.
3. **Semantics own behavior.** Measurement belongs to Part I, capacity drift to Part II, closure to Part III. Shared chrome does not impersonate paper-specific mechanisms.
4. **Progressive enhancement is architectural.** The archive is complete without JavaScript. Motion, pointer response, and view continuity are optional layers over a stable document.
5. **No decorative dependency.** A visual mechanism must communicate route, evidence, capacity, containment, authority, return, or closure. Otherwise it is removed.
6. **Performance is a design constraint.** Budgets are not raised to excuse an effect.
7. **Accessibility states are first-class compositions.** Keyboard, reduced motion, forced colors, print, touch, and narrow screens are designed states rather than fallback accidents.
8. **Comments explain invariants.** Comments describe why a constraint exists, not what obvious syntax already says.
9. **The generated tree must reconcile.** Source, runtime assets, HTML, metadata, and preservation records must agree in CI.
10. **Fewer concepts, more precision.** When two mechanisms can be expressed by one well-named state, the duplicate is deleted.

## Review questions

- Can a new maintainer locate the canonical fact without searching generated HTML?
- Does a class or custom property name describe research meaning rather than appearance alone?
- Does a browser feature fail closed into a complete static document?
- Can the visual identity survive without color?
- Does the interaction become quieter as the reader enters long-form text?
- Does Part III end by returning authority and reducing energy rather than rewarding continued interaction?
- Is any custom build logic more complicated than the bytes it saves justify?

The target is not clever code. The target is code that feels inevitable.
