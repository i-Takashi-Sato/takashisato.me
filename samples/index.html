Before / After

業務設計で変えるのは、資料の見た目ではなく、確認できない状態そのものです。

Before

記録されない運用

口頭指示に依存し、担当者ごとに確認範囲が変わり、記録欄がなく、引き継ぎ時に例外処理が消える状態です。

  • Memory dependent
  • No owner record
  • No review state
After

確認できる構造

確認項目、担当者、時刻、レビュー状態が残り、日次・週次で状態を見直せる運用記録へ変えます。

  • Checklist state
  • Owner / time / reason
  • Review enabled

Operational Shelf

各サンプルは、「何が壊れているか」「何を記録するか」「どう運用に残すか」を示すための断片です。実案件では、業種・人数・既存ルール・確認者・納品形式に合わせて再設計します。

01

Daily Checklist

記憶と口頭指示 → 確認と記録

飲食店・小売店など、スタッフ5〜10名規模の開店前後、営業中、締め作業を確認漏れなく回すためのチェックリストです。

Preview Fragment

開店前：入口、床、客席、カウンター周辺の状態確認。基準：汚れ、破損、異物、備品不足がないこと。記録：確認者名 / 時刻。

  • 全体を見る
  • 業務手順書・SOP設計

02

Control Sheet

分散した確認 → 状態の記録

少人数の店舗・営業チーム・管理部門で、売上、案件、採用、教育、KPIの確認が口頭や個別Excelに分散している状態を整理するための管理表です。

Preview Fragment

案件：進行中案件、未対応、保留事項。入力内容：担当者、期限、状態、次アクション。確認頻度：日次 / 週次。

03

HR Documents

人によって変わる教育 → 基準と記録

採用基準、教育内容、試用期間中の確認、評価理由が担当者ごとにばらついている状態を整理するための文書セットです。

Preview Fragment

教育：初日説明、基本動作、禁止事項、確認手順。基準：誰が教えても最低限の内容が揃うこと。記録：教育担当者 / 完了日。

From sample to operation.

公開サンプルは完成テンプレートではありません。実際の業務内容、人数、既存資料、確認頻度に合わせて、使える形へ再設計します。

既存のメモやExcelがある場合は、その内容をもとに、手順・確認・例外記録・責任者確認へ分解します。
